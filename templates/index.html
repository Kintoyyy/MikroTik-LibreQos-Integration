 Topology & Limits

    

      

        

          
          

            
            ×
          

          
network.json node size = sum of its devices' max rates × this

        

        

          
          

            
            ×
          

          
Log a warning when the busiest top-level/CPU node carries this many times the lightest one's load

        

        

          
          

            
            ×
          

          
cpu / Auto CPU with sticky assignment: move devices (cpu) or whole sites/routers (Auto CPU) only when the busiest CPU node exceeds this many times the lightest

        

      

      

        

          
          

            
            Mbps
          

          
Download one core can shape. 0 = lqos.conf generated_pn_download_mbps. LibreQoS guide by single-thread score: 1000 → 1 Gbps, 1500 → 2, 2000 → 3, 3000 → 4, 4000 → 5 Gbps

        

        

          
          

            
            × fair share
          

          
Split a site across CPUs, or a router into shards, when it carries more than this × one core's share of all plans. 0 = only when above Core Capacity

        

        

          
          

            
            per sync
          

          
Most sites/routers moved between CPUs in one sync (each move rebuilds their queues). 0 = auto (1% of them, 1–32)

        

      

      

          
          
          
      

      

        

          
          
          
Warn when one CPU queue approaches the tc class ID limit (TC_U16_OVERFLOW)

        

        

          
          
          
LibreQoS without a license shapes only the first 1000 circuits (MAPPED_CIRCUIT_LIMIT). 0 = no warning

        

      

    

  


  
  

    
 Instant PPP Updates (webhook)

    

      

        

          
          

            
            s
          

          
Wait this long after a router's call so a burst of logins is handled in one sync (at least 1 s: an ended session must be gone from /ppp active)

        

        

          
          

            
            s
          

          
Webhook syncs run at most this often; each one that changes a file runs the LibreQoS update

        

        

          
          

            
            users
          

          
More logins/logouts than this from one router in one batch (e.g. after it rebooted): read the whole router instead of each user

        

      

      
Turn the webhook on and install it on each BRAS on the Routers page. These apply without a restart.

    

  


  
  

    

       Burst a short boost above the plan, for all traffic
      —
    

    

      

        After a subscriber's line has been idle, the next transfer gets about N seconds' worth of their plan at full speed,
        then settles to the plan. It applies to every transfer equally — page loads, updates and speedtests alike.
        Bursts pause automatically while the LibreQoS link is busy, so they only use spare capacity.
        Applies within ~10 seconds; no restart needed.
      

      

        
      

      

        

          
          

            
            sec of plan
          

          
Burst size = plan rate × this

        

        

          
          

            
            MB
          

          
Upper limit per subscriber, for fast plans

        

        

          
          

            
            % busy
          

          
Link use (of lqos.conf capacity) that switches bursts off

        

        

          
          

            
            % busy
          

          
Bursts return after 30 s below this

        

      

      

         The busy check uses [queues] downlink_bandwidth_mbps / uplink_bandwidth_mbps
        in lqos.conf — set them to your real internet capacity on the LibreQoS tab, or bursts never pause.
        The burst speed itself is not capped (it is limited by the link), so tell subscribers about it, e.g. "short transfers up to …".
